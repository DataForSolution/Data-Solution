# AIF360 fairness reconstruction audit

## Provenance

The three later optimized-preprocessing notebooks preserve Colab provenance pointing to:

`https://github.com/Trusted-AI/AIF360/blob/master/examples/demo_optim_data_preproc.ipynb`

They are modified AIF360 example notebooks, not independent implementations of Optimized Preprocessing.

`Data-450_Assign3B-AIF360.ipynb` is not the substantive fairness experiment; it mounts Drive and attempts to read another `.ipynb` file first with `pandas.read_csv` and then as text.

## Filename/code mismatches

### RF notebook is not Random Forest

The RF-labelled and MLP-labelled notebooks differ in only one code cell, and that difference is an added comment:

`# Code for computing Balanced Accuracy and Disparate Impact with RandomForestClassifier`

The executable classifier remains:

`MLPClassifier(hidden_layer_sizes=(100,), max_iter=300, random_state=42)`

The saved RF metrics are therefore MLP metrics.

### German notebook runs Adult

The German-labelled notebook changes the classifier to `LogisticRegression()` but leaves `dataset_used = "adult"`. Its output should be interpreted as another Adult/sex run, not German Credit.

## Methodological caveat: transformed labels

The inherited AIF360 workflow calls `OP.transform(..., transform_Y=True)` for training and test data. Optimized Preprocessing is designed to transform features and may transform labels as part of its fairness/distortion optimization.

Therefore a classifier evaluated against `dataset_transf_test.labels` is not necessarily being scored against the same targets as a classifier evaluated against `dataset_orig_test.labels`. This is a legitimate design choice for the original algorithm/demo, but it changes the estimand.

The reusable portfolio metric code avoids this ambiguity by requiring one fixed `y_true` reference for each direct comparison.

## Other reproducibility issues

- The notebooks run `pip install 'aif360[all]'` inside the notebook.
- They later uninstall Matplotlib and pin `matplotlib==3.1.3`, producing dependency resolver warnings in the saved run.
- AIF360 itself warns in the saved output that `OptimPreproc` does not use the privileged/unprivileged group arguments passed to initialization in the way a reader may assume; the protected attributes are handled by the preprocessing function/optimization.
- The final Markdown table for Adult/German/COMPAS is inherited from the official example and should not be presented as results generated by the modified classifier notebooks.

## Responsible use

A fairness evaluation should state:
- protected attribute and group coding,
- favorable outcome definition,
- population and exclusions,
- reference labels/estimand,
- threshold-selection procedure,
- utility metric,
- fairness metrics and their direction,
- uncertainty/sample size,
- and why the selected fairness definition is appropriate to the application.
